# judgment-failure-attribution — 失败先归因，再决定动作

本文件是 `judgment` 的细则之一。它只给**归因与动作选择**；归因流程的既有实现、重试策略的具体参数，以 owner 文档为准。

## 1. 铁律

**连续失败时，第一个念头不能是"再试一次"。** 未归因的重试把两种完全不同的故障当成同一种处理，结果是把一次可修的参数错误拖成一轮不可解释的失败。

## 2. 失败三分类（按原因，不按现象）

| 类别 | 判据 | 典型证据 |
|---|---|---|
| **A 工具本身坏了** | 同一调用在输入不变时**稳定**失败；或工具/服务不可达、返回内部错误 | 与参数无关；换个等价输入仍同样失败；日志指向工具内部 |
| **B 参数或指令给错了** | 失败随输入变化；报错指向路径、编码、类型、schema、字段名 | 同一条命令在别的路径/别的编码下成功；错误信息含具体字段或格式 |
| **C 任务本身不该这么做** | 前两类都不成立：环境未就绪、前提未满足、该事项不在本轮边界内 | 前置步骤未完成；用户目标里根本没这一项 |

**归因失败的常见方式**是把 C 当成 A（"工具不行"）然后熔断，或把 B 当成 C（"这不该做"）然后摘除。两者都会让本该完成的工作消失。

**强制例外（拒绝类）**：权限拒绝、审批未通过、沙箱或策略拦截**不属于 A/B/C 任何一类**。它们在输入不变时稳定失败，形式上像 A，但含义是"这条路被明确禁止"——因此**不得熔断后降级，也不得换等价手段绕过**，只能按本文件第 5 节的格式停止并上报。

## 3. 四动作与选择条件

| 动作 | 什么时候 | 什么时候不要 |
|---|---|---|
| **熔断**（停止调用该工具） | 判为 A，且替换路径存在 | 判为 B 时熔断＝掩盖参数错误 |
| **降级**（换等价手段完成同一目标） | 判为 A，无替换路径但目标仍可达 | 降级后结果口径变了却不告知用户 |
| **回退重试**（改输入/改指令后再试**一次**） | 判为 B，且能指出具体错在哪 | 说不出改了什么就重试＝碰运气 |
| **摘除**（把该项移出本轮范围） | 判为 C，或 A 且无降级路径 | 被摘除项其实是本次目标的一部分 |

回退重试的上限是"**改一次、试一次**"：第二次仍失败，说明归因错了，回到第 2 节重判，而不是再试第三次。

## 4. 领域失败不是工具故障（强制例外）

在有限元/机器学习这类数值域里，失败的语义与软件工具失败**相反**，不得套用上面的归因-重试-放弃链条：

- **求解器不收敛**：可能是物理上就该不收敛（网格、边界条件、材料参数的真实反映），属于结果，不是故障。
- **GPU 作业排队未启动**：是队列的正常状态，不是"命令没生效"，**不要**因此重发作业或判失败。
- **OOM / 显存不足**：是资源约束，要按该域的既有纪律缩小规模或排队，不是重试。
- **作业被外部取消、内存接近上限**：按该域的事故记录与纪律处理。

这类现象的处置**归 `compute-resource-discipline.md` 的 R1/R2/R3 与例外登记**，本文件不定义其阈值，也不授权用"放弃"绕过队列纪律。

判据：**该现象是否是软件工具层面的故障**（工具不可达、编码/路径错误、返回内部错误）？是 → 走第 2 节做 A/B/C 归因；否（数值、资源、队列现象，**即便由本次参数引起**）→ 领域失败，走本节，不重试、不降级、不放弃。

## 5. 上报格式（与前文"停止与上报"一致）

归因结论必须能被人复算：

1. 失败的第几次调用、原始命令。
2. 判为 A/B/C 的**证据**（不是印象）。
3. 已排除的类别及排除依据。
4. 选择的动作 + 为什么不是另外三个。
5. 若选择摘除：该项如何回到下一轮，需要什么前置条件。

## 6. 归谁管

- 委派型子代理的失败归因与续接语义：`dispatch-gpt-subagent` 与其 `references/failure-attribution.md`（子代理侧优先，本文件不覆盖）。
- 长时工具调用被杀/结果未知的处理：`tool-call-hard-rules`（**仅当当前技能域提供它**；不提供时按第 5 节停止并上报，不自定重试策略）。
- 计算类失败的资源纪律与例外：`compute-resource-discipline.md`（**仅当本预设提供该文档时**；不提供时按第 5 节停止并上报，**不得自定阈值**）。
