# 判断（Judgment）

这个技能不教你怎么写，只教你**什么时候不写**、**写到哪停**、**什么时候放弃并上报**。

普通函数只有输入输出；Agent 还多出三件东西——**有判断**（该不该做）、**会放弃**（做不成要收手）、**会失控**（越权、扩大范围、把简单问题做复杂）。这三件事没有任何工具能替你兜底，只能靠纪律。

## 何时加载

- 任务开放、多步、或结果不可逆（改配置、动共享预设、批量重写）。
- 你正准备**扩大范围**：从一个文件扩到一棵树，从一个回合扩到长期流程。
- 你正准备**扇出**：派子代理、跑工作流、并行多路。
- 同一类工具/命令**连续失败**，而你的下一个念头是"再试一次"。
- 上下文接近上限，而你想靠"再读几个文件"缓解。
- 有人要求"顺手把周边也做了"。

## 何时不要加载（反触发清单）

加载不是免费的：它会占掉本该用于干活的注意力与窗口。以下情形**不要**加载：

- 单步、确定、可一次做完的动作（读一个文件、跑一条已知命令、改一行拼写）。
- 纯问答、纯解释、纯检索结论——没有边界取舍的问题。
- 已被 owner 文档完整覆盖、且本次不涉及边界判断的领域操作（例：已按 `compute-resource-discipline.md` 排队的 GPU 作业）。
- 用户在既有流程内明确授权的连续小步推进（此时流程本身已经承担了判断）。

判断"要不要加载"本身就是一次判断：**判据是"这次决策会改变行动吗"**；若答案是不会，跳过。

## 第一问：确定流程，还是自主判断

在挑工具、挑方案之前先问这一句。选错的代价不对称：把确定性任务交给自主判断，换来的是不稳定与成本；把开放性任务塞进硬编码流程，换来的是做不对。

| 问 | 若"是" | 若"否" |
|---|---|---|
| 步骤能否在执行前写全？ | 用确定流程：脚本/有序命令，**不要**上 agent | 继续看下一行 |
| 每步的输入是否已知、无需临场取舍？ | 确定流程 | 需要自主判断 |
| 失败模式是否可枚举、可穷举处理？ | 确定流程 + 显式错误分支 | 自主判断 + 熔断/上报 |
| 任务量小到一次能做完？ | 直接做，两个都不上 | 上流程或上判断 |

一句话：**能编排就不判断，能判断就别编排**。

## 三个预算

把"Agent 与函数的差别"折算成三个可以提前分配的预算；预算是有限的，花完就停。

- **判断预算**：一次任务里你最多比较几个方案、最多改几次主意。超出即停止比较，选当前最优并记录理由。
- **放弃预算**：允许你在什么条件下判定"这轮做不成"。放弃不是失败，**假装做成**才是失败。
- **失控预算**：允许你触碰多大的范围（几个文件、几棵目录、能否改共享配置）。超出即停下并请示。

## 边界决策表

每一行都必须同时给出**判据**（凭什么触发）、**动作**（触发后做什么）、**反例**（什么情况下不这么做）。这三列是本表的核心：**判据**决定是否触发，**动作**决定做什么，**反例**用来防止误触发。

| 场景 | 症状 | 判据 | 动作 | 反例 | owner 文档 |
|---|---|---|---|---|---|
| 工具连续失败 | 同一调用第 3 次仍失败，下一个念头是"再试" | 必须先分清是**工具本身坏了**还是**参数/指令给错了** | 工具坏：熔断 + 降级；参数错：回退重试**一次**并改写指令；两者都不是：把该项从本轮任务摘除并上报 | 反例：环境尚未就绪（服务未起、文件未落盘）——先修环境，不算失败重试 | 失败归因细则见 `dispatch-gpt-subagent/references/failure-attribution.md` |
| 上下文将满 | 窗口接近上限，你想靠多读几个文件缓解 | 先判断哪些信息**结论化**了、哪些还是流水账 | 先按 `context-handoff` **外化**，再压缩摘要，再按优先级腾位：历史结论、用户目标、当前子任务必保；过程流水账可丢 | 反例：下一步就要用到、且无法重建的原文（如一次性的探测输出）——先落盘再丢 | 阈值与外化时机归 `context-handoff` |
| 评估一个 Agent | 只看任务完成率就下结论 | 完成率只能证明"能做完"，不能证明"该不该做" | 同时看两件坏事：**不该行动时行动了**、**把简单问题搞复杂了**；两者都要计数 | 反例：探索性任务本就该多走几步——先按任务类型分组再比较 | 详见 `judgment-context-and-evaluation.md` |
| 多智能体 | 想靠"多派几个子代理"提速 | 任务能否拆成**独立且并行**的小块 | 不能拆：单智能体；能拆：先估沟通成本（交接损耗、口径漂移、结果合并），只在净收益为正时才拆 | 反例：子任务彼此依赖、需要频繁对齐——拆开只会更慢 | 详见 `judgment-context-and-evaluation.md` |
| 任务越开放 | 手上事情做完了，范围开始自己长出来 | 新增的部分是否属于**用户本次要的**边界内 | 知道什么时候不写：停手，把"看到了但没做"的清单交出去 | 反例：不做就会立刻让本次结果无效的前置修复——那是边界内 | 计划深度归 `create-a-plan` / `create-a-big-plan` |
| 领域失败 | 求解器不收敛、GPU 作业排队未启动、OOM | 该现象是否是**软件工具层面的故障**（不可达、编码/路径错误、返回内部错误） | **领域失败不是工具故障**：即便由本次参数引起，也按该领域的既有纪律处理，不归因后重试、不降级、不放弃 | 反例：同一条命令在环境正常时成功、现在报编码/路径错误——那才是真工具故障 | 归 `compute-resource-discipline.md` 的 R1/R2/R3（本预设未提供该文档时：停止上报，不自定阈值） |
| 被拒绝 | 权限拒绝、审批未通过、沙箱或策略拦截，重试仍拒 | 这次失败是否意味着"这条路被明确禁止" | **不属于工具故障**：不熔断后降级，不换等价手段绕过，按"停止与上报格式"交出 | 反例：因路径写错被沙箱拦下——那是参数错误（B 类），改正后重试一次 | 见 `references/judgment-failure-attribution.md` 第 2 节强制例外 |

若某行给不出**反例**，说明该行的**判据**太宽，会误触发；若给不出**动作**，说明它只是口号，不能留在表里。

## 停止与上报格式

决定"不做/不做完"时，必须按这个格式交出，否则等于把问题丢给下一个人重犯：

1. **我停在哪一步**：最后一次成功的位置（可回滚点）。
2. **已排除的假设**：试过什么、凭什么排除（带证据，不带感觉）。
3. **当前证据**：命令、输出、文件:行号。
4. **下一步选项**：2–3 个可选路径，各自代价。
5. **反例检查**：我这次停手，会不会正好落在上面某行的"反例"里？若是，则不该停。

宁可交出"没做完 + 证据 + 选项"，也不要交出"看起来做完了"。

## 与既有规范的优先级

- 本技能是**加性**的：它只补判断层。凡某项阈值、流程或安全边界已被 owner 文档拥有（如 `context-handoff`、`compute-resource-discipline.md`、`dispatch-gpt-subagent/references/failure-attribution.md`、`dsh-planning-workflow.md`、`create-a-big-plan`），**以 owner 文档为准**，本技能不复述、不覆盖、不改写其条款。
- **owner 必须可读**：上面点名的 owner 文档若当前预设并未提供（例如 `context-handoff` 与 `compute-resource-discipline.md` 只在部分预设中存在），不要自行补出一套阈值或流程——按"停止与上报格式"交出，并在上报里写明"owner 文档当前不可读"。
- 冲突时以既有纪律为优先：只读审核边界、计算边界（GPU 排队与显存/功耗报告）、委派授权边界，以及 `dsh-planning-workflow.md` 的流程门与 goal 的 Verifier Checklist 完成条件；任何"本技能允许放弃/允许摘除范围/允许提前结束回合"的读法都不得用来放松它们。
- 领域失败（求解器不收敛、排队未启动、OOM）**不是**工具失败：不要对它做"归因后重试"，也不要据此放弃正在排队的作业。
- **被拒绝**（权限、审批、沙箱、策略拦截）不是工具失败：不得降级或换手段绕过，只能停止上报。
